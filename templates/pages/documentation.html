1. Guide Utilisateur (Apprenant)

3. Guide Coordinateurs

Les coordinateurs supervisent leur département et ont accès à une vue synthétique des métriques. Accès : /auth/dashboard/coordinateur/[département]/

Les coordinateurs sont nommés après évaluation de leur candidature sur la plateforme. Leurs identifiants sont générés automatiquement et sont temporaires (changement lors d'une prise de poste).

5. Architecture Technique

Stack principal

  • Framework : Django 6.0.7
  • BDD : SQLite (dev) / PostgreSQL (prod)
  • Cache : LocMemCache (dev) / Redis (prod)
  • Tâches : Celery + Celery Beat
  • Fichiers statiques : WhiteNoise
  • Images : Pillow 12.3.0

Applications Django

  • core : pages publiques, IA, vault
  • users : authentification, dashboards
  • parcours : formations et progression
  • blog : articles et contenu
  • institution : certificats, candidatures
  • messaging : messages et notifications
  • audit : logs immutables
  • forum : communauté
  • gestion : tâches, campagnes, tickets

Variables d'environnement

  • DJANGO_SECRET_KEY — obligatoire
  • OPENAI_API_KEY — assistant IA
  • STRIPE_PUBLIC_KEY — paiements
  • STRIPE_SECRET_KEY — paiements
  • STRIPE_WEBHOOK_SECRET — webhooks
  • REDIS_URL — cache/Celery (optionnel)
  • SENDGRID_API_KEY — emails prod
  • SENTRY_DSN — monitoring (optionnel)

6. Sécurité

Authentification
  • Argon2 (hash de mots de passe)
  • CSRF protection sur tous les formulaires
  • Axes : blocage après 5 tentatives
  • Session sécurisée (HTTPOnly, SameSite)
Réseau & Contenu
  • CSP (Content Security Policy)
  • X-Frame-Options: DENY
  • XSS protection activée
  • HTTPS obligatoire en production
Audit & Monitoring
  • Audit logs immutables (AuditLog)
  • Filtrage de l'IA (questions et réponses)
  • Rate limiting sur les APIs publiques
  • Honeypot anti-bot sur les formulaires
Données sensibles
  • Clés API dans Replit Secrets (jamais en dur)
  • RGPD : consentement tracé
  • Données cryptées en transit (SSL)
  • Sentry DSN pour le monitoring d'erreurs

7. Assistant IA

  • Modèle : GPT-4o-mini (OpenAI)
  • Accessible uniquement pendant les cours (contexte de cours requis)
  • Quota : 10 questions/jour pour les utilisateurs gratuits, illimité en Premium annuel
  • Filtre de contenu double (questions et réponses)
  • Logs d'audit de chaque interaction
  • Endpoint : POST /api/chatbot/ avec { "question": "...", "cours": "contexte du cours" }
  • Configuration : variable OPENAI_API_KEY dans Replit Secrets

8. Paiements Stripe

Flux de paiement

  1. Utilisateur choisit son plan (mensuel/annuel)
  2. Accepte les CGV (case obligatoire)
  3. Redirection vers Stripe Checkout
  4. Paiement sécurisé chez Stripe
  5. Webhook checkout.session.completed
  6. Activation automatique de l'abonnement

Configuration

  • STRIPE_PUBLIC_KEY : clé publique
  • STRIPE_SECRET_KEY : clé secrète
  • STRIPE_WEBHOOK_SECRET : secret webhook
  • URL webhook : /auth/paiement/webhook/
  • Sans clés : message d'information affiché

10. Guide Développeurs

# Installation et démarrage
git clone [repo]
pip install -r requirements.txt
cp .env.example .env        # configurer les variables
python manage.py migrate
python manage.py init_test_data   # crée les utilisateurs de test
python manage.py runserver 0.0.0.0:5000

# Commandes utiles
python manage.py createsuperuser      # admin Django
python manage.py collectstatic        # fichiers statiques
python manage.py makemigrations       # créer les migrations
python manage.py shell                # shell interactif
python manage.py init_test_data       # données de test

Structure des templates

templates/
├── base.html           # Template de base
├── index.html          # Page d'accueil
├── auth/               # Authentification
├── admin/              # Dashboards admin/gestionnaire
├── pages/
│   ├── utilisateur/    # Dashboard étudiant
│   ├── entreprise/     # Premium, checkout
│   ├── support/        # FAQ, contact, blog
│   ├── parcours/       # Formations
│   └── legal/          # CGU, confidentialité
└── errors/             # Pages d'erreur 403/404/500

Conventions importantes

  • Templates app-specific sous pages/<app>/
  • Templates admin sous admin/
  • Templates auth sous auth/
  • Données sensibles : Replit Secrets uniquement
  • Rôles : etudiant, gestionnaire, coordinateur, dg
  • Toujours vérifier est_active() sur l'abonnement
  • L'IA nécessite le contexte du cours (cours)

12. Déploiement

Avant la mise en production

  • Définir DJANGO_DEBUG=False
  • Configurer PostgreSQL (remplacer SQLite)
  • Ajouter les vraies clés Stripe
  • Configurer SendGrid pour les emails
  • Activer Redis pour Celery
  • Supprimer les données et comptes de test
  • Configurer ALLOWED_HOSTS avec le domaine réel

Variables Replit Secrets

Toutes les clés sensibles doivent être dans Replit Secrets (jamais dans .env) :

  • SESSION_SECRET
  • OPENAI_API_KEY
  • STRIPE_PUBLIC_KEY / STRIPE_SECRET_KEY
  • STRIPE_WEBHOOK_SECRET
  • SENDGRID_API_KEY
